# Drafts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any signed-in Foundation pilot can create a private `#<name>` draft arena they own at once, invite pilots, fly in it, request to go public, and (once approved) publish updates to the live arena.

**Architecture:**
- Pure rules (names, who may enter, which files travel, backups) live in `Dare.Arenas.Core` with unit tests.
- Draft records extend `ArenaStore`. `RoleIn` and `RolesFor` learn `#` arenas, so today's grant, settings and upload paths work inside drafts unchanged.
- The plugin adds commands, entry control, approve-from-draft, publish and rollback, plus a small web API.
- A static `/build/` page on the site drives it. The browser client's "+ CREATE" opens `/build/`.

**Tech Stack:** C# (.NET 9, SubspaceServer v4 plugin, Microsoft.Data.Sqlite, xUnit), static HTML/JS on Caddy, Rust/JS for the client hook.

**Spec:** `docs/superpowers/specs/2026-11-24-arena-builder-design.md` (the "Drafts" section and "Decided by Chris").

Repos:
- dare-zone worktree `~/dare-zone/.claude/worktrees/zone-directory` (branch `zone-directory`). Build with `dotnet build src/Dare.Arenas`, test with `dotnet test`.
- Task 6 is in the dare-client worktree `~/oss-src/play-polish` (branch `play-polish`).

## Global Constraints

- Draft arena name is `#` + a name passing `ArenaName.TryValidate` (3–15 chars, a–z/0–9, starts with a letter, no trailing digit, not reserved). The public name is the same without `#`, with no rename.
- A draft and its public name are reserved together. Refuse creating a draft if `#<name>` or `<name>` exists, is requested or reserved, or a folder of either name exists.
- One draft per pilot. A pilot holds at most one name (their draft and its live arena share it).
- Up to 5 invites per draft (`ArenaStore.MaxCoMods` is 5 too). Invitees must have a Foundation account (`AccountStore`).
- Who may enter a draft: owner, co-mods, invitees, global staff mod and up. Anyone else is moved to the public arena with "That arena is a private draft."
- Live arenas change only through Publish. Owner and co-mod content edits on a live arena that has a draft are refused with "Edit your draft #<name>, then publish." Moderation commands still work.
- Publish copies a fixed allow-list: `arena.conf`, the `.lvl` named by `General:Map`, and the `.lvz` files named by `General:LevelFiles`. It copies into staging, then swaps. It keeps the last 3 previous live copies in `arenas/_published/<name>/<utc yyyyMMddTHHmmssZ>/`. One publish per 2 minutes per arena. It refuses if the live arena is suspended or archived.
- The first publish is staff approval of a draft-linked request. Later publishes are by the owner. Every action is a public event.
- A draft untouched (edited or entered) for 30 days is archived to `arenas/_archive/#<name>/` (via `ArchiveFolders`) and frees the slot. Its name stays reserved while the live arena exists.
- Uploaded maps in a `#` arena are stored as `<name>.lvl` (no `#`). The `#` only ever appears as the first character of a folder name.
- Existing owned arenas get a draft automatically on first load: copied from current live files, owned by the owner, co-mods carried over, `live` set. Approving an old-style request also creates the draft.
- Never touch the `[(global)]` staff section. Every file write resolves inside `arenas/#<name>/`, `arenas/<name>/` or `arenas/_published/<name>/`, never through a link.

## Review Focus

- Two pilots race to create the same draft name: exactly one succeeds (Task 2 test `create_draft_twice_same_name_one_wins`).
- An invitee is removed while inside the draft: they're moved out at once, not on their next entry (Task 4 step, live check in Task 7).
- Publish fails halfway (disk or permissions): the live arena keeps its previous files and isn't recycled (Task 3 test `publish_failure_leaves_live_untouched`).
- Upper or mixed case in names (`#SkyRace`, `?go #skyrace`): treated as the same draft everywhere (Task 1 test `draft_names_are_case_insensitive`, Task 2 store tests use mixed case).
- A staff-transferred live arena: the draft follows, and the old owner loses both roles (Task 2 test `transfer_moves_the_draft`).

**Files:**

**Interfaces:**
- Consumes: `DraftRules` (Task 1).
- Produces:
  - Schema:
    - `drafts(name PK NOCASE without '#', owner UNIQUE NOCASE, status TEXT, live INTEGER, created, last_touched)`
    - `draft_invites(name, player, PK(name, player))`
    - `requests.draft INTEGER NULL`, added with `ALTER TABLE` when missing.
    - Draft co-mods live in `comods` with arena `#<name>`.
  - `enum DraftStatus { Active, Requested, Published, Archived }`
  - `record DraftInfo(string Name, string Owner, DraftStatus Status, bool Live, DateTimeOffset Created, DateTimeOffset LastTouched, IReadOnlyList<string> CoMods, IReadOnlyList<string> Invited)`
  - `Result CreateDraft(string owner, string name, Func<string, bool> folderExists, Func<string?> createFolder)`. It refuses:
    - if the owner already has a draft;
    - if the owner owns an arena with a different name;
    - if `name` or `#name` is taken, pending or reserved.
    It runs `createFolder` in the transaction, as `Approve` does, and logs event `draft`.
  - `DraftInfo? Draft(string name)` (with or without `#`), and `DraftInfo? DraftOwnedBy(string player)`
  - `Result Invite(string name, string owner, string player, Func<string, bool> hasAccount)` / `Uninvite(...)`. Cap 5. Owner only.
  - `bool IsInvited(string name, string player)`
  - `Result RequestPublic(string owner, string pitch)`: inserts a request for the public name with `draft = 1`. The draft becomes Requested.
  - `Approve`: on a draft-linked request it calls `createFolder` (the plugin copies the draft), inserts the `arenas` row, and sets the draft to Published with `live = 1`. `Decline` on a draft-linked request sets the draft back to Active. On an old-style request (no draft), `Approve` also inserts a Published, `live` draft `#<name>` for the requester (the plugin's `createFolder` makes both folders).
  - `bool IsLiveWithDraft(string arena)`: arena has a draft with `live = 1`.
  - `Result Published(string name, string owner)`: event `publish`, touches the draft.
  - `bool PublishAllowed(string name, DateTimeOffset now)`: false within 2 minutes of the last `publish` event.
  - `void TouchDraft(string name)`
  - `IReadOnlyList<string> ArchiveIdleDrafts(TimeSpan idle, Func<string,bool> occupied)`: Active, Requested and Published drafts past `idle` become Archived and queue a pending move for `#<name>`.
  - `Result ReviveDraft(string name, string staff)`
  - `int BackfillDrafts()`: for each owned arena without a draft, insert a Published, `live` draft for its owner, copy its co-mods to `#<name>`, and return the count. (The plugin copies the files first.)
  - `RoleIn("#x", p)`: owner if the draft's owner (status not Archived), comod if in `comods` for `#x`, else null. Live arenas keep their roles.
  - `RolesFor(p)` also lists the draft (`#x`, owner/comod) after the owned arena.
  - `Transfer(arena, …)` moves `drafts.owner` too, and clears the old owner's draft invites, keeping co-mods.

### Task 3: Draft folder operations

**Files:**
- Create: `src/Dare.Arenas.Core/DraftFiles.cs`
- Test: `tests/Dare.Arenas.Tests/DraftFilesTests.cs` (temp directories)

**Interfaces:**
- Consumes: `DraftRules.PublishFiles`, `DraftRules.BackupsToDelete`, `ArenaPaths.Resolve`.
- Produces (all `static`, under an `arenasRoot`, returning `string?`: null on success, else a short error):
  - `CreateFromTemplate(arenasRoot, templateDir, draft)`: copies `_template` into `#name`. Refuses if the target exists.
  - `CopyArena(arenasRoot, from, to, IReadOnlyList<string> files)`: allow-list copy into a new folder. Used by approve (draft to public) and backfill (public to draft).
  - `Publish(arenasRoot, draft, live, files, DateTimeOffset now)`, in this order:
    1. Copy `files` from the draft into `_published/<live>/.staging`.
    2. Move the current live allow-listed files into `_published/<live>/<utc>`.
    3. Move the staged files into `arenas/<live>/`.
    4. Prune backups with `BackupsToDelete`.
    If any step fails, put the previous files back and return the error.
  - `Rollback(arenasRoot, live)`: restore the newest backup into `arenas/<live>/` and remove that backup. Returns an error when there is none.
